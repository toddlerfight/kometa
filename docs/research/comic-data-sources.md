# Comic data sources: League of Comic Geeks and alternatives

Research date: 2026-10-10. Scope: data sources Kometa could use for weekly releases, series/issue metadata, collected editions, variant covers, community signals, and collection/reading-list exchange. Every claim cites its source inline. Where a primary page was unreachable (Cloudflare 403, dead host), that is stated and the fallback is flagged as secondary.

Method notes: GitHub facts come from the GitHub REST API (`gh api`) on 2026-10-10; web pages were fetched directly, or with a browser User-Agent via curl where the plain fetch 403'd. `leagueofcomicgeeks.com` itself returned HTTP 403 for every path tried (`/api`, `/comics/import`, `/member/pro`), so LOCG facts rely on its Intercom help centre (`intercom.help/comicgeeks`, reachable without a challenge), on third-party source code, and on Kometa's own prior observations.

### 1.4 Cloudflare

- locg-cli PR #7 (2026-05-19): "Cloudflare now binds `cf_clearance` cookies to the JA3/JA4 TLS fingerprint of the solving browser — `curl_cffi`'s synthesized fingerprint is rejected, causing HTTP 403 on every request"; the fix moved to Playwright with a persistent real-Chrome profile. PR #13 added a homepage warm-up and one retry on 403, because "cold-start GETs and mid-batch `cf_clearance` expiry both fail opaquely". https://github.com/hsukenooi/locg-cli/pull/7 ; https://github.com/hsukenooi/locg-cli/pull/13
- klappstuhlpy/locg-api: "the whole site is behind Cloudflare, which 403s most non-residential IPs"; it fronts requests with FlareSolverr (headless Chrome). https://github.com/klappstuhlpy/locg-api
- Mylar3's weekly pull list is sourced from a community proxy of LOCG (`https://walksoftly.itsaninja.party/newcomics.php`, in `mylar/locg.py`); it returned HTTP 523 (origin down) on 2026-10-10 and an open PR describes it as down. https://github.com/mylar3/mylar3/blob/master/mylar/locg.py ; https://github.com/mylar3/mylar3/pull/1833
- Kometa's own note (2026-10-08): the import burst tripped the wall; LOCG is now browser-pass only with a pasted `cf_clearance`. Memory `project_locg_block_2026-10-08.md`.

### 2.3 Grand Comics Database (GCD)

The GCD's HTML site and `docs.comics.org` wiki returned HTTP 403 to every fetch from this host (plain and browser-UA), including `/download/`, `Data_Distribution`, `Current_Schema` and `App_Guidelines`. However, the GCD's REST API at `https://www.comics.org/api/` answered 200 anonymously from the same host. Facts below come from that live API, the GCD's own code repository, its GitHub wiki, and projects that consume the dumps; dump cadence is flagged as secondary.

#### 2.3.1 Licence and attribution

- Site legal footer (from the Django template): "All portions of the Grand Comics Database™, except where noted otherwise, are copyrighted by the GCD and are licensed under a Creative Commons Attribution-ShareAlike 4.0 International License (CC BY-SA 4.0). This includes but is not necessarily limited to our database schema and data distribution format." Cover thumbnails "are used for identification purposes only. All rights to cover images reserved by the respective copyright holders." Site code is GPL. https://github.com/GrandComicsDatabase/gcd-django/blob/master/templates/gcd/bits/legalese.html

- The GCD's own `App_Guidelines` wiki page (referenced by ComicTagger's maintainer in discussion #608) was unreachable (403); its text could not be quoted. https://github.com/GrandComicsDatabase/gcd-django/discussions/608

#### 2.3.4 GCD vs Metron data model (for an offline-fallback decision)

| Dimension | GCD | Metron | Source |
|---|---|---|---|
| Issue number | `Issue.number` is a free-text `CharField(max_length=50)` plus `volume` text, `sort_code` integer for ordering, and a derived `descriptor` (e.g. `12`, `[nn]`, `v2#3`). Decision inputs: the dump is the only zero-rate-limit path (offline SQLite, CC BY-SA attribution required, no images, bi-weekly refresh unverified). The live API is attractive for ad-hoc lookups (cover URL, story credits as text, ISO-week releases) but is rate-limited to 30/hour anonymous or 2,000/day with a free account, is explicitly unstable in field format, and may drop anonymous access. Numbering/date normalisation (string `key_date` with `00` placeholders, free-text `number`) and text-rendered credits mean a loader must parse, not map, to reach Metron's typed shape; Metron's `gcd_id` provides the join key.

### 5.2 Ranked recommendation for Kometa

Given Kometa already caches LOCG variant lists and uses Metron:

1. **Listing (which variants exist):** Metron `issue.variants` first (authenticated, header-governed, stable, includes `sku`/`upc`), then the cached LOCG `variant-cover-list` scrape as the enrichment pass for far-ahead solicits and retailer/convention exclusives Metron lacks, at a trickle budget. GCD API `variant_of` rows third, for historical issues.
2. **Images:** Metron `variant.image` (served, stable URLs) → LOCG S3 covers (already cached by Kometa; keep local copies, since Cloudflare can cut the source) → GCD API `cover` (w400, one per variant row, 30/hour anonymous — fetch lazily, attribute GCD). Do not rely on ComicVine `associated_images`; do not mirror VerseDB images (ToS).
3. **Types (ratio / incentive / exclusive / virgin / reprint):** no surveyed API returns a typed enum. Derive a local taxonomy by parsing name strings in this precedence: distributor solicit titles (bracketed ratio `[1:25]`, "INCV", "CVR C", "Virgin", "2nd Ptg" on PRH/Lunar pages — most regular grammar), then Metron `variant.name` (+ `sku` as the distributor key for joining to solicit rows), then LOCG variant titles mapped onto LOCG's five subscription classes (Open Order / Incentive / Reprint / Facsimile / Other), then GCD `variant_name`. VerseDB is the only source claiming a structured `variant type` + `ratio` field; probe it with a free token to confirm the fields and the PRO gate before building on it, and treat it as read-only enrichment under its non-commercial ToS.
4. **Join keys:** `sku` (Metron variant) ↔ distributor item code (solicits); `upc` (Metron variant / GCD `barcode`) ↔ CLZ/VerseDB barcode lookups; `gcd_id` on Metron issues ↔ GCD rows; LOCG `variant` id stays Kometa-internal.

### What this means for Kometa

1. Keep Metron as the primary catalogue; its published burst limit is 20/min, so Kometa's ~30/min client ceiling should be lowered to the header-driven limits and honour `Retry-After` (https://github.com/Metron-Project/metron/blob/master/api/RATELIMIT.md). An API token is the recommended auth and never expires by default.
2. There is no path to an official LOCG key: no sign-up, an unanswered 2024 request, and a credible statement that it is retailer-only. Do not plan around `/api`.
3. LOCG remains the only source of pull counts/ratings and the freshest far-ahead solicitations. Every active scraper in 2026 has moved to a real browser (Playwright/FlareSolverr) because Cloudflare binds `cf_clearance` to the solving browser's TLS fingerprint; Kometa's pasted-cookie + curl_cffi approach is the same design locg-cli abandoned in May 2026, and should be treated as best-effort with hard request budgets.
4. For weekly releases without LOCG, Metron covers most of the pull list (27–28/30 in the 2026-10-08 probe) and ComicList is a free distributor-aggregated backstop (no ids; title/issue/price only). The Diamond/Previews feed is dead; Shortboxed is Cloudflare-walled.
5. Collection and reading-list exchange is file-based: LOCG's free Excel export/import (series/issue/publisher/date; ratings; Patron adds cover price and value) and CBL XML are the de facto formats. If Kometa wants to push a shelf to LOCG, generate the "League of Comic Geeks (Default)" CSV the way mylar-league does and expect title+date matching losses.
6. GCD's SQLite dump (CC BY-SA 4.0, free account, ~6 GB, no images, bi-weekly refresh unverified) is the only bulk-offline, rate-limit-free option and the right tool for credits/ISBN/back-catalogue backfill; Metron's `gcd_id` is the join key. Loading it means parsing free-text `number`, `key_date` with `00` placeholders and story-level credits into Kometa's issue-level shape, and attributing the GCD in the UI.
7. The GCD also has a live, anonymous REST API (`/api/issue/{id}/` with a w400 cover URL and text credits; `/api/issue/on_sale_weekly/{year}/week/{week}/`) at 30 requests/hour anonymous or 2,000/day with a free account; useful for lazy per-issue lookups, not for sweeps, and the maintainers say fields are unstable and anonymous access may end.
8. Comic Vine stays a secondary id-bridge (Metron exposes `cv_id`); its 200/resource/hour and non-commercial terms are confirmed on the API page, and its `associated_images` are not a dependable variant-image source.
9. Marvel's API is retired, DC has none, and distributor data (Lunar, PRH) is retailer-portal HTML with CSV only behind retailer logins; those public solicit titles are nevertheless the most regular grammar for ratio/incentive variant parsing.
10. VerseDB is a real, current, comics-only catalogue with a documented token API (300 reads/hour free), a structured variant model (type, artist, ratio), LOCG/CLZ CSV import and iCal feeds, but its data is sourced partly from ComicVine/GCD/Metron and its ToS forbids scraping, caching or commercial use; probe the `/issues/{id}/variants` fields with a free token before designing around it.
11. Variant covers: Metron for listing and images, LOCG cache for freshness and exclusives, GCD API for historical covers, distributor solicits for ratio parsing; no surveyed source returns a typed variant enum, so the taxonomy stays a Kometa-side parser (§5.2).
